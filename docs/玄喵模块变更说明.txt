玄喵模块变更说明（RAG + 语音 + 流式对话升级）
========================================================

一、这次比之前新增了什么
1. 问答主链路改为 RAG：
   用户提问 → 本地知识库检索 → 拼装上下文 → 后端 SSE 流式生成 → 打字机逐字显示 + 语音播报。
   不再依赖 XunFeiTest WebSocket，不再只靠固定关键词回复。
2. 本地知识库：
   7 份 txt 文件覆盖三星堆总述、青铜神树、纵目面具、青铜大立人、金杖、黄金面具、青铜工艺。
   检索算法：专有名词映射 + 标题词匹配 + 双字分词重叠度，取最高分文档。
3. 浏览器语音输入：
   基于 Web Speech API，支持 Chrome/Edge，对话框和主聊天页都有麦克风按钮。
4. 思考等待态：
   回答前轮播"玄喵正在思考中…""正在整理资料…"等提示语，每 2.4 秒切换。
5. 固定回复瘦身：
   只保留"你好/在吗/你是谁"等打招呼匹配，其余全部走 RAG。
6. 回答更短更聚焦：
   系统提示词强制 60-120 字、最多 3 句，知识文档只取首句 80 字注入 prompt。
7. 三层兜底：
   知识未命中 → 诚实说"不确定"；SSE 失败 → buildFallbackReply 简短判断；全链路断 → "稍后再问我吧"。

四、协同开发注意
   1. 知识文档格式约定：
      - 首行 = 标题
      - 末行 = 元数据（实体ID：xxx | 朝代：xxx | 出土地点：xxx | 工艺：xxx）
      - 中间 = 正文，每份 200-500 字
      - 新增主题时同步在 knowledgeSearch.js 的 DOC_FILES 和 ALIAS_MAP 里加条目
   2. 浏览器语音输入仅支持 Chrome/Edge，Firefox/Safari 按钮自动禁用。
   3. 调体验优先改 startTypewriterAndSpeech 的 options 参数：playDelayMs / charDelay / thinkingIntervalMs。
   4. WebSocket 代码（initWS/handleMessage）还在但已不参与问答，RAG 稳定后可整段删除。
   5. RAG 现在只取 top1 文档，若后续需要多文档融合改 askWithRag 里的 searchKnowledge(question, 1) 第二个参数。
   6. PromptManage.java 的 prompt 是所有 AI 对话共用，改这里会影响主聊天页和玄喵两处。
