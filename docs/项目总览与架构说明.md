# 青铜数元项目总览与架构说明

## 1. 一句话介绍

青铜数元是一套面向三星堆文博场景的数字展示系统：用户可以探索文物、查看三维模型、浏览关系图谱，并通过 AI 文博助手进行带来源的知识问答和多模态交互。

## 2. 用户体验链路

```text
进入时空探索
  → 按时间、空间或工艺筛选文物
  → 查看文物详情与三维模型
  → 浏览相关年代、遗址、工艺和文化含义
  → 向 AI 文博助手提问
  → 由 RAG 返回带来源的资料
  → 由 Agent 根据当前文物和页面状态执行导览或页面动作
  → 返回结果并更新前端状态
```

## 3. 核心模块

### 知识检索

后端扫描 `springboot/knowledge-vault/wiki` 下的 Markdown 文档，解析标题、标签、关联页面和来源信息，建立轻量词法索引。标题、元数据和关系会影响排序，检索结果会保留原文片段和来源信息。

### Agent

Agent Router 根据用户问题和上下文输出四类结果：工具调用、RAG、直接回答和不支持。工具执行受到白名单、参数校验、超时和异常降级约束。前端和后端共同维护当前文物、页面、导览节点、最近动作和上一次结果。

### 多模态

图片通过多模态聊天接口传给视觉语言模型，音频和视频经过对应解析服务后再进入问答上下文。媒体创作采用任务化流程保存状态和结果，生成内容会保留相应的内容标识。

### 三维与图谱

Three.js负责加载 GLB 文物模型，AntV G6负责关系图谱。两者通过文物实体 ID 与后端数据关联。图谱查询可以使用 Neo4j，也可以回退到 MySQL结构化数据。

## 4. 数据流

### 普通问答

```text
Vue页面
  → POST /api/ai-chat/stream
  → 会话与上下文读取
  → Agent Router
  → RAG检索或直接回答
  → SSE返回回答、引用和状态
  → Vue更新消息和页面
```

### 工具调用

```text
用户请求
  → Router生成结构化路由
  → 后端解析和置信度检查
  → 工具白名单检查
  → 参数与上下文校验
  → 执行一次主要工具
  → 返回工具结果和状态
```

### 图谱展开

```text
当前文物 entityId
  → 请求图谱接口
  → Neo4j查询或MySQL回退
  → 返回 nodes / edges
  → G6绘制
  → 点击或展开节点后继续请求邻居
```

## 5. 数据库和配置

- MySQL保存用户、文物、业务、会话、消息、附件、引用和媒体任务；
- Neo4j用于可选的图谱查询，默认关闭；
- `heritage_db.sql`用于基础数据库初始化；
- `docs/sql/competition-p0.sql`用于竞赛功能的增量字段；
- `docs/neo4j-graph-seed.cypher`用于图谱种子数据；
- `application-template.yml`是公开配置模板，真实 `application.yml` 不提交 Git。

## 6. 公开版本边界

该项目当前是一个面向演示和研究验证的可运行系统，不宣称已经完成大规模生产部署。当前词法检索适合小规模文档，知识库扩大后需要加入混合检索和离线评测；当前三维和图谱主要通过实体 ID 联动；回归脚本可以本地执行，但还没有完整的持续集成流水线。
